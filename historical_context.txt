# Nader Pay Agent — Architecture Documentation

## 1. Overview

Nader Pay Android has been rebuilt from a Payment Gateway into a pure **Agent/Worker** application. It runs on an Android device, listens for Vodafone Cash SMS messages, matches them against shipping requests created in Nader AI, and reports payment evidence back to Nader AI for verification.

**Key shift:**
- **Old role:** Payment Gateway exposing merchant APIs and webhooks.
- **New role:** Agent that polls Nader AI, reads SMS, parses transactions, matches orders, and sends verification evidence.

## 2. Actors

| Actor | Responsibility |
|-------|---------------|
| Nader AI (Server) | Creates shipping requests, receives evidence events, runs verification engine, updates request status. |
| Nader Pay Android (Agent) | Polls server, reads SMS, parses Vodafone Cash, matches orders, sends evidence, caches state. |
| End User (Agent Owner) | Logs in, registers device, configures settings, monitors dashboard. |

## 3. High-Level Flow

1. User signs in with Supabase Auth.
2. User registers this Android device with Nader AI via Edge Function.
3. Agent starts polling for `payment_requests` with `payment_type = 'shipping'`.
4. On incoming SMS, `SmsListener` forwards the message to the `AgentContext`.
5. `smsParser` extracts amount, sender phone/name, recipient wallet, transaction id.
6. `matchingEngine` scores the transaction against active orders.
7. If the match is confident and `autoConfirm` is enabled, the agent sends `payment_evidence_detected` event to the server.
8. The server (`verification-engine`) verifies the evidence and updates the request status.

## 5. Core Components

### 5.1 AgentContext
- Holds `settings`, `deviceState`, `agentState`.
- Starts polling when signed in and device registered.
- Processes incoming SMS messages via `handleMessage`.
- Provides `registerDevice`, `refreshOrders`, `setEnabled`, `saveAgentSettings`, `requestSmsAccess`.

### 5.2 SmsReader / SmsListener
- `readExistingVodafoneCashMessages()` reads historical SMS from the Android inbox (using `react-native-get-sms-android`).
- `AgentSmsListener` renders only on Android and uses `useSmsListener` from `expo-sms-listener` to forward new messages.
- Both paths normalize and deduplicate messages by a composite id.

### 5.3 Polling Worker
- Uses `setInterval` driven by `settings.pollingIntervalMs`.
- Calls `refreshOrders()` which queries `payment_requests` where `payment_type = 'shipping'`.
- Caches results in SQLite and sends heartbeat to Nader AI.
- Stops automatically when signed out or agent disabled.

### 5.4 Matching Engine
- Scores each parsed transaction against active orders.
- Criteria: amount tolerance (50%), sender phone (25%), sender name (15%), recipient wallet (10%).
- A match is `confirmed` when score ≥ 70.
- Ambiguous matches (top two scores within 10 points) are rejected for manual review.

### 5.5 Evidence Sender
- Sends `payment_evidence_detected` event to `POST /device-api/{device_id}/events`.
- Includes `messageHash` to prevent duplicate submission.
- The server returns whether the event was accepted or duplicate.

## 6. Local SQLite Schema

| Table | Purpose |
|-------|---------|
| `agent_settings` | Key-value store for agent settings. |
| `orders_cache` | Cached `payment_requests` from Nader AI. |
| `processed_transactions` | Idempotency: transaction_id → status. |
| `agent_events` | Audit log of agent actions and errors. |

## 7. Backend Edge Functions

### 7.1 device-api
- `POST /device-api/register-with-auth`
  - Authenticates user via JWT.
  - Creates `device` row.
  - Returns `device_id` + `device_token`.
- `POST /device-api/{device_id}/heartbeat`
  - Updates `last_seen_at`, `listener_status`, `sync_status`.
- `POST /device-api/{device_id}/events`
  - Ingests `payment_evidence_detected` events.
  - Calls `verification-engine` asynchronously.

### 7.2 verification-engine
- Existing function reused unchanged.
- Validates transaction uniqueness, updates `payment_requests` status, creates `verification_results`.

## 8. UI/UX

- **Minimal aesthetic:** generous whitespace, clear hierarchy, no shadows or decorative colors.
- **Three tabs:**
  - **Home:** status, stats, recent matches.
  - **Orders:** list of shipping requests with status chips.
  - **Settings:** agent toggle, Supabase URL/key, polling interval, auto-confirm, device registration, sign out.

## 9. Security & Permissions

- Sensitive tokens stored in `expo-secure-store` (iOS/Android) or `localStorage` on Web.
- Android SMS permissions declared in `app.json`.
- Runtime SMS permission request via `expo-sms-listener`.
- Device registration uses user JWT; subsequent heartbeat/events use device token.
- All external API calls go through Supabase Edge Functions; no direct third-party calls from client.

    29   let p = phone.replace(/[\s\-\(\)]/g, '');
    30   if (p.startsWith('+20')) p = '0' + p.slice(3);
    31   if (p.startsWith('20') && p.length === 12) p = '0' + p.slice(2);
    32   return p;
